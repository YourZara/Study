4.1 Design Procedures for Combinational Logic Circuits

A Combinational Logic Circuit is a type of digital circuit whose output at any given instant depends strictly and solely on the present combination of inputs. Unlike sequential circuits, combinational circuits contain no memory elements (flip-flops), no internal state storage, and no feedback loops.

Fundamental Characteristic

For $N$ input variables, there are $2^N$ possible binary input combinations. For each combination, there is exactly one possible output state defined by the logic equations: $Y_j = f_j(X_0, X_1, \dots, X_{N-1})$.

4.1.1 Standard 5-Step Design Methodology

  1. Problem Specification: Clearly state the real-world operational requirements, identify all input variables, and define required output signals.
  2. Variable Assignment & Input/Output Mapping: Assign distinct algebraic letter symbols (e.g., $A, B, C$ for inputs; $S, C, Y$ for outputs) to all input and output lines.
  3. Truth Table Construction: Construct a complete truth table listing all $2^N$ input combinations alongside their required output logic states ($0, 1,$ or Don't Care $X$).
  4. Boolean Function Simplification: Derive algebraic expressions for each output using Karnaugh Maps (K-Maps), Quine-McCluskey, or Boolean postulates to achieve minimal Sum-of-Products (SOP) or Product-of-Sums (POS).
  5. Logic Circuit Realization & Verification: Draw the final gate-level schematic diagram using target logic gates (AND/OR/NOT, XOR, or Universal NAND/NOR gates) and verify correct logical functionality.

4.2 Half-Adder and Full-Adder

4.2.1 Half-Adder (HA)

A Half-Adder is a combinational circuit that performs the arithmetic addition of two single binary bits ($A$ and $B$). It generates two outputs: Sum ($S$) and Carry ($C$).

4.3 Half-Subtractor and Full-Subtractor

4.3.1 Half-Subtractor (HS)

A Half-Subtractor subtracts bit $B$ from bit $A$ ($A - B$) and yields two outputs: Difference ($D$) and Borrow ($B_{out}$).

InputsOutputsSubraction Operation ($A - B$)
ABBorrow (Bout)Difference (D)
0000$0 - 0 = 0$
0111$0 - 1 = -1 \implies 2 - 1 = 1$ (Borrow 1)
1001$1 - 0 = 1$
1100$1 - 1 = 0$

Equations: Difference $D = A \oplus B$, Borrow $B_{out} = \bar{A} B$.

4.3.2 Full-Subtractor (FS)

A Full-Subtractor calculates $A - B - B_{in}$, incorporating an incoming borrow $B_{in}$.

InputsOutputsOperation Logic
ABBinBoutDifference (D)
00000$0 - 0 - 0 = 0$
00111$0 - 0 - 1 = -1 \implies D=1, B_{out}=1$
01011$0 - 1 - 0 = -1 \implies D=1, B_{out}=1$
01110$0 - 1 - 1 = -2 \implies D=0, B_{out}=1$
10001$1 - 0 - 0 = 1 \implies D=1, B_{out}=0$
10100$1 - 0 - 1 = 0 \implies D=0, B_{out}=0$
11000$1 - 1 - 0 = 0 \implies D=0, B_{out}=0$
11111$1 - 1 - 1 = -1 \implies D=1, B_{out}=1$

Full Subtractor Derived Equations:

  • Difference ($D$): $A \oplus B \oplus B_{in}$
  • Borrow Out ($B_{out}$): $\bar{A}B + \bar{A}B_{in} + BB_{in} = \bar{A}B + B_{in}(\overline{A \oplus B})$
Full Subtractor using 2 Half-Subtractors & 1 OR Gate

HS₁ produces $D_1 = A \oplus B$ and $B_1 = \bar{A}B$.
HS₂ takes $D_1$ and $B_{in}$ to produce $D = D_1 \oplus B_{in} = A \oplus B \oplus B_{in}$ and $B_2 = \bar{D_1} B_{in} = (\overline{A \oplus B}) B_{in}$.
Combining borrows through an OR gate yields: $B_{out} = B_1 + B_2 = \bar{A}B + B_{in}(\overline{A \oplus B})$.

4.4 Ripple Carry Adders and Fast Adders

4.4.1 N-Bit Ripple Carry Adder (RCA)

A Ripple Carry Adder is constructed by cascading $N$ Full Adders in series. The carry output $C_{i+1}$ from stage $i$ is connected directly to the carry input $C_i$ of stage $i+1$.

The Ripple Propagation Delay Bottleneck

In an $N$-bit Ripple Carry Adder, bit $N-1$ cannot calculate its correct sum until the carry ripples through all preceding $N-1$ stages. If each Full-Adder stage has propagation delay $T_{FA}$ (typically 2 gate delays), the total delay for an $N$-bit addition is:

T_total = N × T_FA = 2N Gate Delays

For 32-bit or 64-bit ALUs, this propagation delay causes significant performance penalties.

4.4.2 Fast Adder: Carry Lookahead Adder (CLA)

To eliminate ripple delays, a Carry Lookahead Adder (CLA) generates all carry signals simultaneously in parallel using high-speed lookahead logic gates.

Derivation of CLA Equations:

For any stage $i$ of an adder, define two signals:

  • Carry Generate ($G_i$): $G_i = A_i \cdot B_i$ (Stage generates a carry regardless of incoming carry)
  • Carry Propagate ($P_i$): $P_i = A_i \oplus B_i$ (Stage propagates incoming carry to next stage)

The Sum output is $S_i = P_i \oplus C_i$, and the Carry output is $C_{i+1} = G_i + P_i C_i$.

By recursively expanding $C_{i+1}$, we write all carry equations purely in terms of initial inputs $A_i, B_i$ and initial carry $C_0$:

C₁ = G₀ + P₀ C₀ Carry for Bit 1 (2 gate delays)
C₂ = G₁ + P₁ C₁ = G₁ + P₁ (G₀ + P₀ C₀) = G₁ + P₁ G₀ + P₁ P₀ C₀ Carry for Bit 2 (2 gate delays)
C₃ = G₂ + P₂ C₂ = G₂ + P₂ G₁ + P₂ P₁ G₀ + P₂ P₁ P₀ C₀ Carry for Bit 3 (2 gate delays)
C₄ = G₃ + P₃ C₃ = G₃ + P₃ G₂ + P₃ P₂ G₁ + P₃ P₂ P₁ G₀ + P₃ P₂ P₁ P₀ C₀ Carry for Bit 4 (2 gate delays)
Why CLA is Fast

Every carry $C_1, C_2, C_3, C_4$ is generated in **exactly 2 gate delays** (one AND layer for products, one OR layer for sum) regardless of bit width $N$. Thus, total addition time drops from $O(N)$ to $O(1)$ constant time (typically 4 gate delays total: 1 for $P_i/G_i$, 2 for Lookahead Carry Generator, 1 for final Sum XOR).

4.5 Multiplexers (MUX) Design

A Multiplexer (MUX), or "Data Selector", is a combinational circuit that selects binary information from one of $2^n$ input lines and directs it to a single output line based on $n$ select lines.

4.5.1 4-to-1 Multiplexer (4:1 MUX)

Contains 4 data inputs ($I_0, I_1, I_2, I_3$), 2 selection inputs ($S_1, S_0$), an Enable input ($\bar{E}$), and 1 output ($Y$).

1XX0 (Disabled)

Boolean Equation for 4:1 MUX:

Y = Ē · [ S̄₁ S̄₀ I₀ + S̄₁ S₀ I₁ + S₁ S̄₀ I₂ + S₁ S₀ I₃ ]

4.5.2 Implementing Arbitrary Boolean Functions using MUX

An $n$-variable Boolean function can be implemented using a $2^{n-1}$-to-1 MUX (with $n-1$ selection lines connected to $n-1$ variables, and the remaining variable connected to the data inputs).

Worked Example: Implement $F(A, B, C) = \sum m(1, 3, 5, 6)$ using a 4:1 MUX

1. Use variables $A$ and $B$ as select lines ($S_1 = A, S_0 = B$).
2. Variable $C$ will be applied to data lines $I_0, I_1, I_2, I_3$.
3. Construct the Implementation Table:

Decoder vs Demultiplexer Equivalence

A decoder with an Enable input line ($\bar{E}$ or $E$) functions identically to a Demultiplexer where the Enable signal is treated as Data Input $D$.

4.7 Basic Encoders

An Encoder performs the inverse operation of a decoder. It accepts $2^N$ (or fewer) input lines and compresses them into an $N$-bit binary output code.

Derived Logic Equations:

  • $Y_2 = D_4 + D_5 + D_6 + D_7$
  • $Y_1 = D_2 + D_3 + D_6 + D_7$
  • $Y_0 = D_1 + D_3 + D_5 + D_7$
Severe Limitations of Basic Encoders
  1. Multiple Active Inputs Malfunction: If $D_3$ and $D_6$ are both 1 simultaneously, output becomes $111_2 = 7_{10}$, which is completely invalid.
  2. Ambiguity with Input $D_0$: When all inputs $D_0 \dots D_7$ are 0, output is $000$, making it indistinguishable from active $D_0 = 1$.

4.8 Priority Encoders

A Priority Encoder solves basic encoder defects by enforcing a strict priority hierarchy among inputs. If two or more inputs are active concurrently, the input with the highest priority index is encoded, and lower priority active inputs are ignored.

4.12.1 Common Cathode vs. Common Anode Configurations

4.13 Magnitude Comparators

A Magnitude Comparator is a combinational circuit that compares two binary numbers $A$ and $B$ and determines their relative magnitudes, producing three output flags: $A > B$, $A = B$, and $A < B$.

4.13.1 1-Bit Magnitude Comparator

ABA > BA = BA < B
00010
01001
10100
11010

Equations: $(A > B) = A \bar{B} \quad, \quad (A < B) = \bar{A} B \quad, \quad (A = B) = A \odot B = \overline{A \oplus B}$.

4.13.2 4-Bit Magnitude Comparator (7485 IC Architecture)

To compare two 4-bit numbers $A = A_3 A_2 A_1 A_0$ and $B = B_3 B_2 B_1 B_0$, define bit-wise equality variables $x_i = A_i \odot B_i$ for $i \in \{0, 1, 2, 3\}$.

Full 4-Bit Comparison Equations:

(A = B) = x₃ · x₂ · x₁ · x₀ All bits must match exactly
(A > B) = A₃ B̄₃ + x₃ A₂ B̄₂ + x₃ x₂ A₁ B̄₁ + x₃ x₂ x₁ A₀ B̄₀ Cascade checking from MSB to LSB
(A < B) = Ā₃ B₃ + x₃ Ā₂ B₂ + x₃ x₂ Ā₁ B₁ + x₃ x₂ x₁ Ā₀ B₀ Cascade checking from MSB to LSB
